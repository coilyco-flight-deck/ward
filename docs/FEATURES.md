# ward features

Inventory of what `ward` ships.

## Scope

Contributor-facing cli-guard gate: repo dev verbs + audited host wrappers.

## Commands

- **`ward exec <verb>`** - run a repo dev verb (`.ward/ward.yaml`) through cli-guard: argv-validated, one JSONL audit row, clean+synced gate. See [exec-verb.md](exec-verb.md).
- **`ward pkg brew <verb>`** - audited brew wrapper: formula/tap mutations default to primary-org taps (`--allow-untapped` else); reads pass through.
- **`ward upgrade`** - audited self-update, OS-branched: `brew upgrade coilyco-flight-deck/tap/ward` on macOS/Linux, `scoop update ward` on Windows (`--dry`). On Windows `scoop update ward` self-blocks on the running `ward.exe`, so the app update is detached to a background powershell that waits for this PID to exit before running scoop (result in `%TEMP%\ward-upgrade.log`). See [ward#561](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/561), [ward#568](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/568).
- **`ward audit {path,tail}`** - read the audit log: `path` prints its path, `tail` streams rows (`--since`/`--follow`). See [audit.md](audit.md).
- **`ward git <verb>`** - audited passthroughs, concurrency-safe `commit`, destination-gated `clone` ([ward#285](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/285)), ephemeral-clone `grep`/`grep-remote` ([ward#369](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/369)), and pre-configured Forgejo auth on the network verbs (`fetch`/`pull`/`push`/`clone`) so they never drop to a username/password prompt ([ward#507](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/507)). See [git-verbs.md](git-verbs.md).
- **`ward setup`** (`warded setup`) - scaffold `.ward/ward.yaml` from the Makefile, run doctor. See [setup.md](setup.md).
- **`ward doctor`** - diagnostic checks against the config + host: the allowlist drift guard, the host security probes, a host-side local-harness Ollama-reachability probe ([ward#499](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/499), the pre-dispatch mirror of the [ward#487](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/487) launch gate), and ([ward#450](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/450)) a fail-by-default gate when a repo declares no `security:` block. See [doctor.md](doctor.md).
- **`ward exec lint-refs`** - lint issue refs in public-facing docs so every one resolves for a GitHub reader ([ward#446](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/446)): a terse `ward#123` never autolinks in a rendered Markdown file on the mirror, so `scripts/lint_issue_refs.py` (also a pre-commit gate) requires full-URL links and `--fix` rewrites them.
- **`ward hook pre-tool-use`** - Claude Code PreToolUse hook: binary-path check + bare-command deny with routing hints.
- **`ward install-hooks`** - register the PreToolUse hook in `.claude/settings.json`.
- **`ward agent {engineer,director,advisor} [--driver <name>]`** (public face: **`warded <role> <ref>`**) - startup-role roster: `engineer` implements detached, `director` a heartbeat surfacing a read-only session + triage, `advisor` answers without code (a ref comments or fans cross-repo work into per-repo issues, trust-gated; [ward#424](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/424)). A startup role's host/cloud capability (the `~/.aws` mount, the tailnet route) is **guardfile membership in `ward-kdl.fleet.kdl`'s `roles` block**, not a first-class ward flag ([ward#578](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/578)): the advisor holds the live-observe set (aws + tailscale guardfiles) and reaches them with no flag, the engineer/director hold none, and the demoted `--aws`/`--tailnet` survive one release as hidden back-compat aliases (`advisor --no-tailnet` is the isolation opt-out). The `~/.aws` mount only forwards the dispatch host's identity - it mints none - so when the capability is on but the host has no creds there (docker would mount an empty dir, and `ssm` calls fail `NoCredentials` silently), ward prints a loud launch-time warning naming the fix rather than reading as delivered ([ward#579](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/579)). **Every** warded role (engineer, director, advisor) auto-mounts the target's own `catalog.dependsOn` upstreams as **read-only** reference clones ([ward#573](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/573), widened from advisor-only): distinct from the writable `--repo` grants, deduped against them and the substrate set, and excluded from the reaper's push-verify ([container-multi-repo.md](container-multi-repo.md)). The set is resolved **in-container from the fresh clone**, never the host cwd ([ward#580](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/580)), so a dispatch from an unrelated working directory still mounts the *target's* deps. Every role dispatches only for a compiled-in [trusted owner](agent-trust-gate.md). See [agent](agent.md).
- **`--workflow direct-main|pr|patch-only`** *([ward#508](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/508))* - the dispatched engineer's **landing policy**: `direct-main` (default) merges to `main` and closes (unchanged); `pr` opens a branch + pull request; `patch-only` posts a patch with no landing authority. The mode shifts the seed, rides the container env + a `ward.workflow` label, and gates the reaper's `main` push. See [agent-workflow.md](agent-workflow.md).
- **`ward agent reap`** *([ward#376](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/376))* - the **host-side idle-killer**: an engineer exits when done, so one still `Up` but log-silent past `--idle` (default **1h**) is wedged. It `docker stop`s the running `ward.role=engineer` containers past the threshold (idle from the last container-log timestamp, else start time), unless a `--max-cpu` guard spares a busy one; interactive roles are idle by design and untouched. `--interval` runs it as a standing daemon, `--dry-run` previews. See [agent-reap.md](agent-reap.md).
- **`ward container {reap,bootstrap}`** *(hidden, entrypoint-internal; [ward#263](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/263))* - in-container plumbing: `reap` lands/salvages on teardown, records dispatch-time provenance, requires proof that the run landed new history after the reservation before it can read as done, enforces the carried issue's same-repo `closes #N` before `main` can land, short-circuits a landed-and-closed run as nothing-to-reap before any salvage gate so it cannot false-salvage, posts a genuine salvage notice back on the carried issue (reopening it) instead of a standalone mega-issue ([ward#518](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/518)), dumps a structured `--- reap diagnostics ---` block to stderr + the salvage notice on every salvage/failure ([ward#531](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/531)); a dispatch version guard refuses to install a ward **older** than the dispatching host unless `--allow-ward-downgrade` is passed, so a stale pin cannot ship an already-fixed false-salvage bug into the container ([ward#529](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/529)), and it verifies each `--repo` grant landed ([ward#291](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/291)); `bootstrap` is the PID-1 entrypoint port ([ward#181](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/181)). See [reap](container-reap.md) and [provenance](container-reap-provenance.md).
- **Reserving an issue road-blocks steering it** *([ward#494](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/494))* - a `ward agent` reservation makes the [reserved-means-immutable](agent-reserved-immutable.md) rule visible and, where the forge allows, enforced. The `🔒 Reserved` comment carries an explicit directive - do not comment on or edit the issue to steer a run in flight, a correction goes to a **new issue, dispatched fresh** - and right after posting it the run best-effort **locks the conversation** where the API supports it: a GitHub-hosted run seals the issue (`PUT /issues/{n}/lock`) so a non-collaborator is blocked and a write-access architect meets a deliberate "unlock to comment" road-block, while **Forgejo (no lock API, `is_locked` read-only) leaves the comment as the road-block** and logs the skip. The lock never fails the reservation, and a pre-launch [release](agent-reservation.md) unlocks again. See [reserved means immutable](agent-reserved-immutable.md).
- **Agent-run observability** *([ward#363](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/363), [ward#532](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/532), [ward#510](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/510), [ward#547](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/547))* - a detached `ward container drain-exit` waiter drains a run **shortly after its container exits** (blocking on `docker wait`), so a just-closed run is observable at once rather than only when the keep-10 sweep evicts it; the sweep is the idempotent backstop, draining every exited run's console + transcript + secret-free `meta.json` before `docker rm`, routed to a selectable **sink** (`WARD_AGENT_SINK`: `signoz` | `disk` | `both`); the local-exclusive default ships the whole run to the local SigNoz and persists nothing to disk, gated so full/unredacted content reaches only a loopback endpoint (a remote endpoint falls back to redacted envelopes), retiring the disk+logdy workflow; ward also emits stable lifecycle lines during dispatch, bootstrap, and reap under a documented convention (a `container=<name>` correlation id spanning host terminal, `console.log`, and `meta.json`; [ward#517](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/517), see [container-lifecycle-logs.md](container-lifecycle-logs.md)); the [director read-only surface](agent-surface.md) binds a disk-sink drain dir read-only at `/opt/ward-agent-logs` so a director reads run logs without a docker socket ([ward#525](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/525)), and now also pulls a read-only ward-kdl helper into the container so it can inspect kai-server without mutation ([ward#547](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/547)); the bound source is a **redacted** parallel drain tree scrubbed by the same redaction the SigNoz export uses ([ward#526](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/526)). See [agent-observability.md](agent-observability.md).
- **`ward agents list [--json]`** - dump the fleet roster from `fleetconfig.Fleet`; `--json` is the stable read surface [agentic-os](https://github.com/coilysiren/agentic-os) (`aos`) reads ([ward#417](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/417)). See [agents-list](agents-list.md).
- **Selectable GitHub token source** *([ward#533](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/533))* - the GitHub dispatch lane provisions its token per `WARD_GITHUB_TOKEN_SOURCE`, defaulting to `env` (the publishable static-env-var path): `env` reads `WARD_GITHUB_TOKEN`/`GH_TOKEN`/`GITHUB_TOKEN`, `gh` mints a fresh token host-side via `gh auth token`, and `app` ([ward#534](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/534)) mints a short-lived, repo-scoped GitHub App installation token at dispatch: it signs an RS256 App JWT from a private key fetched from an operator-configured SSM param (`WARD_GITHUB_APP_ID` + `WARD_GITHUB_APP_KEY_SSM`), resolves the target repo's installation, and exchanges the JWT for a token scoped to that one repo. Resolution stays host-side and env-only in-tree - the App key's SSM param name rides an env var, never a baked path. See [agent-github.md](agent-github.md).

## Agent harness seam

- **Per-agent folders own their behaviour** *([ward#425](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/425))* - each harness is an `agentsapi.Agent` in `internal/agents/<name>/` owning its capability bodies; core dispatches through the registry by feature-test (no per-agent `switch`); a ratchet blocks its return. See [agentsapi.md](agentsapi.md).

## Spec-driven ops (`ward-kdl`)

`ward-kdl` is the build-time authoring layer ([docs/ward-kdl.md](ward-kdl.md)): permission surfaces + fleet configs for `ops`, `docker`, `agents`, `pkg` ([surface](ward-kdl-surface.md)), plus `ward-kdl.fleet.kdl`. It builds into `ward-kdl-{read,write,admin}` tiers ([ward#240](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/240)) - not public artifacts ([ward#455](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/455)), authors build from a clone ([authoring](ward-kdl-authoring.md)). Two exceptions publish to an **internal** Forgejo package channel keyed to the release tag: `publish-kdl-write` pushes the `write` tier the broker reads ([ward#501](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/501), [broker.md](broker.md)), and `publish-kdl-read` pushes the `read` tier a sealed read-only director pulls for its non-mutating observe surface ([ward#547](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/547), [ward#572](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/572)). The deployment bundle lives in sibling `agentic-os/ward-specs/`.

The **exec-dialect** guardfiles auto-mount at their `wrap` path; `git` / `pkg brew` keep hand-written surfaces ([ward#284](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/284)), plus a **ward=true-gated** `ward docker exec` shell-into-a-run leaf ([ward#220](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/220), [ward-docker-exec.md](ward-docker-exec.md)). See [in-ward](ward-kdl-in-ward.md).

## Eco content pipeline

- **`ward eco test`** *([ward#582](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/582), [coilyco-gaming/eco-ops#30](https://github.com/coilyco-gaming/eco-ops/issues/30))* - the Eco content pipeline. It boots a **throwaway** EcoServer with the working-copy mod/config change on the local (Windows) Steam install and runs a **fail-closed smoke gate**: the server must reach ready with NO ModKit load exception ([coilyco-gaming/eco-ops#7](https://github.com/coilyco-gaming/eco-ops/issues/7)) and no UserCode compile failure, and every `--mod` must report loaded. On a green gate, `--promote` (off by default - the first real run is Kai's) drives a guarded auto-promote to the live kai-server: **snapshot** `Mods/`+`Configs/` -> apply -> restart -> **health probe** -> **canary watch** -> healthy (promoted) | degraded (**auto-rollback** + restart, fail loud on a rollback that does not recover). The live world only ever ends green or reverted. Safety-critical logic is pure and unit-tested in ward; the live-side steps are the infrastructure-repo `eco-server-{snapshot,health-check,rollback}.sh` scripts driven over ssh ([coilyco-gaming/eco-ops#26](https://github.com/coilyco-gaming/eco-ops/issues/26)). Config is env/flag driven (`WARD_ECO_*`), never baked into `.ward/ward.yaml`. The design to dissolve this compiled pipeline into a `ward ops eco` guardfile ([ward#585](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/585)) lives in [ops-eco.md](ops-eco.md). See [eco-test.md](eco-test.md).

## Examples & demo

- **`examples/toy/`** - ward's minimal, dependency-free managed repo (Makefile + `.ward/ward.yaml` with a `security:` block + a ward-kdl guardfile), the demo and spec-bundle anchor. See [example-repo.md](example-repo.md).
- **`examples/demo.sh`** *([ward#251](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/251))* - the runnable launch demo: one happy path (`ward exec test` + audit row + clean-tree gate) plus two danger classes refused live - repo danger via the hard cli-guard argv gate, infra/cloud danger (`kubectl`/`aws`) via the protected-binary hook. Every denial is real ward output, honest about which mechanism holds ([enforcement-boundary.md](enforcement-boundary.md)). See [demo.md](demo.md).

## Release pipeline

- **Release notes** *([ward#486](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/486))* - "does it affect you" verdict. [release-notes.md](release-notes.md).
- **Dual-forge binary matrix** *([ward#454](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/454))* - `ward-{darwin,linux,windows}-{amd64,arm64}` (windows as `.exe` + per-asset `.sha256` sidecar for scoop, [ward#561](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/561)) + `SHA256SUMS`, built once per tag and published byte-identical to both the Forgejo and GitHub release pages, so their checksums match. [release-binaries.md](release-binaries.md), [github-mirror.md](github-mirror.md).
- **Push-not-poll package manifests** *([ward#571](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/571))* - the tag build writes every install channel: `bump-tap-formula` bumps the homebrew tap and `bump-scoop-manifest` writes `bucket/ward.json` into the Forgejo scoop bucket at release time, so `scoop update ward` no longer lags a daily autoupdate poll. [release.md](release.md).
