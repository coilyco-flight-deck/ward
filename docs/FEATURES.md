# ward features

Inventory of what `ward` ships.

## Scope

Contributor-facing cli-guard gate: repo dev verbs + audited host wrappers.

## Commands

- **`ward exec <verb>`** - run a repo dev verb (`.ward/ward.yaml`) through cli-guard: argv-validated, one JSONL audit row, clean+synced gate. See [exec-verb.md](exec-verb.md).
- **`ward pkg brew <verb>`** - audited brew wrapper: formula/tap mutations default to primary-org taps (`--allow-untapped` else); reads pass through.
- **`ward upgrade`** - audited self-update, OS-branched: `brew upgrade coilyco-flight-deck/tap/ward` on macOS/Linux, `scoop update ward` on Windows (`--dry`). On Windows `scoop update ward` self-blocks on the running `ward.exe`, so the app update is detached to a background powershell that waits for this PID to exit before running scoop (result in `%TEMP%\ward-upgrade.log`). See [ward#561](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/561), [ward#568](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/568).
- **`ward audit {path,tail}`** - read the audit log: `path` prints its path, `tail` streams rows (`--since`/`--follow`). See [audit.md](audit.md).
- **`ward git <verb>`** - audited passthroughs, concurrency-safe `commit`, destination-gated `clone` ([ward#285](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/285)), ephemeral-clone `grep`/`grep-remote` ([ward#369](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/369)), and pre-configured Forgejo auth on the network verbs (`fetch`/`pull`/`push`/`clone`) so they never drop to a username/password prompt ([ward#507](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/507)). See [git-verbs.md](git-verbs.md).
- **`ward setup`** (`warded setup`) - scaffold `.ward/ward.yaml` from the Makefile, run doctor. See [setup.md](setup.md).
- **`ward doctor`** - diagnostic checks against the config + host: the allowlist drift guard, the host security probes, a host-side local-harness Ollama-reachability probe ([ward#499](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/499), the pre-dispatch mirror of the [ward#487](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/487) launch gate), and ([ward#450](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/450)) a fail-by-default gate when a repo declares no `security:` block. See [doctor.md](doctor.md).
- **`ward exec lint-refs`** - lint issue refs in public-facing docs so every one resolves for a GitHub reader ([ward#446](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/446)): a terse `ward#123` never autolinks in a rendered Markdown file on the mirror, so `scripts/lint_issue_refs.py` (also a pre-commit gate) requires full-URL links and `--fix` rewrites them.
- **`ward exec lint-workflows`** - lint the Forgejo/GitHub `test` workflow mirror ([ward#214](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/214)): the pair stays identical except `runs-on`, and `--fix` regenerates the Forgejo copy. See [workflow-mirror.md](workflow-mirror.md).
- **`ward hook pre-tool-use`** - Claude Code PreToolUse hook: binary-path check + bare-command deny with routing hints.
- **`ward agent director consult`** *([ward#493](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/493))* (public face **`warded director consult`**) - the director's interactive **consult-to-headless conversion interview**: the manual launch-triage loop, encoded. It reads a repo's `consult` + untriaged open-issue queue (scope + trust via the [heartbeat](agent-director.md)'s `--repo`/`--org` path), runs one batched host one-shot on director's own `--harness` to frame each ticket's **single blocking item** - a DECISION only a human holds, or a FACT worth verifying - with a 2-4 option set + recommendation, then walks them with a human at the terminal. Freeform answers welcome. Per ticket the human picks a disposition mapping to a done-condition terminal state: **`[h]eadless`** bakes the answer onto the ticket as a **DECISION comment** (framed decision + answer + attribution/date) and flips `consult` → `headless` so a fresh engineer can carry it, **`[k]eep`** records why it stays consult, **`[c]lose`** closes it as moot, **`[m]erge`** closes it as merged into another issue, `[s]kip`/`[q]uit` defer/end. The comment is posted **before** the label flip so an answer survives a label-write failure; a barred/unwired host one-shot fails **open** to a hand-driven interview rather than fabricating a decision; it is interactive-only (no terminal errors, `--dry-run`/`--print` preview the queue and write nothing) and dispatches nothing itself - the flip to `headless` refills the lane the heartbeat drains, and is the deliberate promotion the automation-mode dispatch ceiling wants. See [director-consult.md](director-consult.md).
- **Director scratch policy** - director-style read-only sessions enforce the workspace clone as read-only and provision `/scratch` as the writable escape hatch for throwaway scripts and temp files. See [container.md](container.md) and [agent-surface.md](agent-surface.md).
- **`ward agent {engineer,director,advisor} [--harness <name>]`** (public face: **`warded <role> <ref>`**) - startup-role roster: `engineer` implements detached, `director` a heartbeat surfacing a read-only session + triage, `advisor` answers without code (a ref comments or fans cross-repo work into per-repo issues, trust-gated; [ward#424](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/424)). A startup role's host/cloud capability (AWS creds, the tailnet route) is **guardfile membership in `ward-kdl.fleet.kdl`'s `roles` block**, not a first-class ward flag ([ward#578](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/578)): the advisor and director hold the live-observe set (aws + tailscale guardfiles) and reach them with no flag - the director so its container joins the tailnet and can observe the live kai-server ([ward#547](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/547)) - the engineer holds none, and the demoted `--aws`/`--tailnet` survive one release as hidden back-compat aliases (`advisor --no-tailnet` is the isolation opt-out). The harness pick is spelled `--harness` or, equally, `--agent` (both first-class per [ward#660](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/660), neither preferred); its old spelling `--driver` survives one release as a hidden deprecated alias, and an explicit first-class spelling wins when the alias is also set. A tailnet-joining dispatch **readies the `ward-tailnet` docker network** before the pull: a host missing it has it **created** (idempotent), not a bare `exit 125` mid-launch, and an unattached ansible-owned `mac-proxy` box only **warns** (the run still launches, the SOCKS5 tower route just will not resolve until that infra role converges) ([ward#597](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/597)). The aws capability **exports the launching host's whole credential chain** (`aws configure export-credentials` - SSO, env, profile, assumed role, IMDS) and injects it as short-lived `AWS_*` env, so the run gets working creds regardless of how the host authenticates and with zero in-container chain replication ([ward#586](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/586)); it runs where the chain resolves (the launching host, a Windows broker host and the broker-forwarded director-surface path included). When export fails (AWS CLI v2 absent) ward falls back to a read-only `~/.aws` mount, which only forwards the host's identity - so when that fallback also finds no creds (docker would mount an empty dir, and `ssm` calls fail `NoCredentials` silently), ward prints a loud launch-time warning naming the fix rather than reading as delivered ([ward#579](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/579)). **Every** warded role (engineer, director, advisor) auto-mounts the target's own `catalog.dependsOn` upstreams as **read-only** reference clones ([ward#573](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/573), widened from advisor-only): distinct from the writable `--repo` grants, deduped against them and the substrate set, and excluded from the reaper's push-verify ([container-multi-repo.md](container-multi-repo.md)). The set is resolved **in-container from the fresh clone**, never the host cwd ([ward#580](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/580)), so a dispatch from an unrelated working directory still mounts the *target's* deps. A `dependsOn` entry may be a **full git clone URL** for an external, non-Forgejo upstream ([ward#612](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/612)): its host + transport are honored (`ssh://git@github.com/...`), and **ward seeds the mirror itself host-side at launch** by cloning it over the **host user's default ssh keychain** (the ambient ssh-agent, then `~/.ssh` identities / `~/.ssh/config` - exactly what a plain `git clone` resolves, no ward-specific key) into the shared gitcache, then a `cp`-only helper lifts the finished bare mirror into the volume so neither the key nor any egress ever enters a container (never mirrored onto Forgejo). A dep that does not hydrate **fails loud** at launch instead of silently reading as present. Every role dispatches only for a compiled-in [trusted owner](agent-trust-gate.md). See [agent](agent.md).
- **`ward container mcporter-hydrate`** *(hidden, entrypoint-internal; [ward#672](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/672))* - the warded-container startup capability that runs the canonical `agentic-os-kai/scripts/merge-mcporter.py` from the mounted `/substrate` bundle and writes `~/.mcporter/mcporter.json` before the harness launches. It keeps mcporter lazy for host use while making `mcporter list` available inside every supported warded harness without depending on infrastructure's generic host setup. See [container.md](container.md).
- **`--workflow direct-main|pr|patch-only`** *([ward#508](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/508))* - the dispatched engineer's **landing policy**: `direct-main` (default) merges to `main` and closes (unchanged); `pr` opens a branch + pull request; `patch-only` posts a patch with no landing authority. The mode shifts the seed, rides the container env + a `ward.workflow` label, and gates the reaper's `main` push. See [agent-workflow.md](agent-workflow.md).
- **`ward agent review` - the in-container adversarial-review panel** *([ward#134](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/134))* - a pre-PR quorum gate the [engineer](agent-engineer.md) seed wires into every headless landing run: after CI is green and before the run opens the PR or merges, the worker's diff must survive a **heterogeneous multi-model panel** of families **other than the worker's own** (a claude worker gets `opencode` (qwen) + `codex` reviewers, never claude - correlated blind spots), each told to **refute** it and default to BLOCK on uncertainty. The gate is `CI green AND quorum >= threshold` and **fails closed** (a reviewer error, timeout, or empty vote blocks the landing, never passes it). The panel is **cost-tiered** - local qwen is the free tier run on every diff, codex the paid tier run only as a tiebreaker or on a high-risk class - and the quorum **threshold tiers by an autonomy class** (`--review-class lint-cleanup|default|refactor`, riding in as `WARD_REVIEW_CLASS`: lint-cleanup passes on one reviewer, default a majority, refactor unanimous). When no heterogeneous reviewer is available it degrades to **advisory-only** with a loud log + a `PR-BODY-NOTE:` the worker copies into the PR body. Each reviewer's structured verdict (verdict, reason, confidence) is persisted to a sidecar log beside the audit trail, and `ward agent review stats [--reverted ...]` surfaces the calibration numbers (pass/block/advisory split per class, plus the false-negative rate of passed-then-reverted diffs). `--no-review-gate` opts a run out. See [dispatch-review.md](dispatch-review.md).
- **`--config` model-context overrides + startup config echo** *([ward#616](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/616))* - every warded run now **echoes its resolved model-context config at container startup** (a greppable `===== ward agent config =====` block: agent, model, effort/reasoning, endpoint, context-level), for **every** agent regardless of whether it writes a config file, so a run's harness config is visible in the log stream rather than silent. The repeatable **`--config agent.<name>.<key>=<value>`** flag overrides those knobs from the CLI (`warded engineer #N --config agent.claude.model=sonnet --config agent.claude.effort=medium`): each dotted path translates to the matching `WARD_*` container env the entrypoint's `envOr` already resolves **over the per-agent fleet default**, so it rides the exact mechanism codex/claude read - claude's `model` is now wired end to end (fleet node -> `WARD_CLAUDE_MODEL` -> `RunCtx` -> `--model` at launch, empty keeping today's bare launch). Unknown keys **fail loud** at plan time with the known-key list, and `--config` is approved on the engineer + advisor dispatch broker allowlists so an in-container director surface forwards it host-side. **Per-role model/effort defaults** now resolve too ([ward#620](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/620)): a `role X { agent claude { model ... reasoning-effort ... } }` overlay in `ward-kdl.fleet.kdl` ([cli-guard#192](https://forgejo.coilysiren.me/coilyco-flight-deck/cli-guard/issues/192)) lets a role's launch config diverge from the flat per-agent default - the **director** claude runs `claude-opus-4-8[1m]` (Opus 4.8, 1M context) at `high` effort for its heartbeat, the **engineer** claude runs the cheaper `claude-fable-5` at `medium` for parallel fan-out (codex likewise: director `gpt-5.5`, engineer `gpt-5.4-mini`), and advisor sets no overlay so it inherits the flat default. The run's config role rides in as `WARD_ROLE` and the overlay slots into the precedence highest-first: `--config` > `WARD_*` env > **per-role overlay** > flat per-agent fleet default. See [agent-config-overrides.md](agent-config-overrides.md), [agent-flags.md](agent-flags.md).
- **Automation-mode dispatch ceiling** *([agentic-os#246](https://forgejo.coilysiren.me/coilyco-flight-deck/agentic-os/issues/246), [ward#607](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/607))* - a dispatch surface runs an issue only when `surface <= mode` on the order `headless > interactive > consult`. The gate lives in cli-guard's `resolveDispatchIssue` (the shared Dispatcher chokepoint), and **ward's own dispatch path narrows that rule for engineer**: `warded` / `ward agent` resolves issues through `resolveAgentWork`, never the Dispatcher, so the code-landing **engineer** role now refuses only issues explicitly labeled `interactive`; consult/default unlabeled issues dispatch normally, and `--force` / `--print` still override the refusal. The `director` and `advisor` roles are supervisory / consultative and ungated (the director is what assigns modes). Because it fires on `resolveAgentWork` (not the TTY pre-flight), the director's non-interactive headless auto-burndown is covered too. ward's forgejo and GitHub issue fetchers populate `Issue.Labels` so both gates can read the mode label; an unlabeled issue fails closed to `consult`, which still dispatches here until a deliberate interactive label appears. The mode labels (`headless`, `interactive`, `consult`) live at org scope beside P0-P4.
- **`ward agent reap`** *([ward#376](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/376))* - the **host-side idle-killer**: an engineer exits when done, so one still `Up` but log-silent past `--idle` (default **1h**) is wedged. It `docker stop`s the running `ward.role=engineer` containers past the threshold (idle from the last container-log timestamp, else start time), unless a `--max-cpu` guard spares a busy one; interactive roles are idle by design and untouched. `--interval` runs it as a standing daemon, `--dry-run` previews. See [agent-reap.md](agent-reap.md).
- **`ward agent stop <ref>`** *([ward#627](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/627))* - the director-surface **on-demand** counterpart to `reap`'s idle sweep: a director that mis-scoped an issue and dispatched an engineer against it can **halt that specific run** instead of commenting a correction and hoping it notices, or asking a human to `docker stop` host-side. It forwards a stop through the same [dispatch broker](agent-surface.md) (a new `Action:"stop"` on the request, back-compat with the launch default), and host ward resolves the target - `owner/repo#N` (matched by the `ward.role=engineer` + `ward.repo` + `ward.issue` labels) or a container name - and `docker stop`s the one match via the **same graceful path reap uses** (no `rm`/`kill`/`exec`). **Stop-only, engineer-only**: a target that resolves to any other role (advisor / director / session) is refused fail-closed with its role named, and a ref matching **zero or more than one** engineer is refused with the candidates listed, never a blind stop. It runs only from a director read-only surface (broker addr set); off-surface it errors like a forwarded dispatch does. `--print` resolves + shows the target and stops nothing. See [agent-stop.md](agent-stop.md).
- **`ward container {reap,bootstrap}`** *(hidden, entrypoint-internal; [ward#263](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/263))* - in-container plumbing: `reap` lands/salvages on teardown, records dispatch-time provenance, requires proof that the run landed new history after the reservation before it can read as done, enforces the carried issue's same-repo `closes #N` before `main` can land, short-circuits a landed-and-closed run as nothing-to-reap before any salvage gate so it cannot false-salvage, treats an **empty repo** (no `origin/main`) as an **establish-main** case - pushing a clean, run-owned commit **as** `main` to create the default branch and fire CI, rather than salvaging a clean run just because the repo started empty ([ward#599](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/599)), posts a genuine salvage notice back on the carried issue (reopening it) instead of a standalone mega-issue ([ward#518](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/518)), dumps a structured `--- reap diagnostics ---` block to stderr + the salvage notice on every salvage/failure ([ward#531](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/531)); a dispatch version guard refuses to install a ward **older** than the dispatching host unless `--allow-ward-downgrade` is passed, so a stale pin cannot ship an already-fixed false-salvage bug into the container ([ward#529](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/529)), and it verifies each `--repo` grant landed ([ward#291](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/291)); `bootstrap` is the PID-1 entrypoint port ([ward#181](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/181)). See [reap](container-reap.md) and [provenance](container-reap-provenance.md).
- **Reserving an issue road-blocks steering it** *([ward#494](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/494))* - a `ward agent` reservation makes the [reserved-means-immutable](agent-reserved-immutable.md) rule visible and, where the forge allows, enforced. The `🔒 Reserved` comment carries an explicit directive - do not comment on or edit the issue to steer a run in flight, a correction goes to a **new issue, dispatched fresh** - and right after posting it the run best-effort **locks the conversation** where the API supports it: a GitHub-hosted run seals the issue (`PUT /issues/{n}/lock`) so a non-collaborator is blocked and a write-access architect meets a deliberate "unlock to comment" road-block, while **Forgejo (no lock API, `is_locked` read-only) leaves the comment as the road-block** and logs the skip. The lock never fails the reservation, and a pre-launch [release](agent-reservation.md) unlocks again. See [reserved means immutable](agent-reserved-immutable.md).
- **Concurrent dispatches don't race onto one issue** *([ward#600](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/600))* - the reservation check and post are not atomic, so two `warded #N` on the same tick could each spin a container (`ward#507` collected four reservation comments in 17s). Three guards close it: a **broker per-ref lock** serializes same-ref dispatches at the host dispatch broker *before* any container starts (the second waits, sees the first's hold, yields with zero wasted spin); a **jittered reservation re-check** is the in-container backstop for paths the broker doesn't cover (two direct host runs, or cross-host) - each run posts, waits a randomized `[5s,15s]` interval (`WARD_AGENT_RESERVE_RECHECK`, `0` disables), re-reads, and yields if a concurrent claim wins the deterministic tiebreak (earliest timestamp, else lexically-min `container@host`), so exactly one run proceeds; and a **closed-issue skip** no-ops with the `issue-closed` dispatch exit code instead of spinning a container to rediscover an already-landed issue (the `#507` restart-loop), `--force` overriding. See [agent-reservation.md](agent-reservation.md).
- **A failed run is self-documenting on the tracker** *([ward#609](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/609))* - a container that dies at the in-container [auth smoke gate](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/222) (stale host creds) is diagnosable from the **issue thread**, no docker logs required. Three surfaces: the **reservation comment** (posted before the gate) folds the **dynamic** per-run seed context into a collapsed `<details>` - resolved ref, branch, driver, run id, dispatch timestamp, workflow, the **issue body as seeded**, and which thread comments were included vs stripped in the pre-flight read - referencing the static doctrine by ward version rather than pasting it, and carrying no comment bodies or secrets; the reaper's **reservation-released comment** names the **specific gate** that failed (`auth` / `ollama-probe` / `bootstrap`), folds in the error line, and gives the recovery step; and a **docker-log echo** prints the same context (plus the seed) as a delimited `ward run context` banner at entrypoint startup, before any gate, as the last-resort backstop. A pre-launch death is also **loud and self-healing** *([ward#595](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/595))*: the reservation-released comment leads with a **"⚠️ Run never started — this issue needs re-dispatch"** headline and a machine-detectable `<!-- ward-needs-redispatch -->` marker (so an orphaned run reads as a call to action, not a benign release a human or heartbeat mistakes for "in flight"), and a `ward agent director` **re-dispatches deterministically** rather than relying on an incidental second attempt landing on a healthy host - its reconcile pass re-queues a dispatched entry whose thread carries a release marker stamped at/after its dispatch, bounded by a 3-attempt cap after which it parks the entry `blocked` as `orphaned-needs-redispatch` for a human, never a livelock. See [agent-reservation.md](agent-reservation.md).
- **Agent-run observability** *([ward#363](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/363), [ward#532](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/532), [ward#510](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/510), [ward#547](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/547))* - a detached `ward container drain-exit` waiter drains a run **shortly after its container exits** (blocking on `docker wait`), so a just-closed run is observable at once rather than only when the keep-10 sweep evicts it; the sweep is the idempotent backstop, draining every exited run's console + transcript + secret-free `meta.json` before `docker rm`, routed to a selectable **sink** (`WARD_AGENT_SINK`: `signoz` | `disk` | `both`); the local-exclusive default ships the whole run to the local SigNoz and persists nothing to disk, gated so full/unredacted content reaches only a loopback endpoint (a remote endpoint falls back to redacted envelopes), retiring the disk+logdy workflow; ward also emits stable lifecycle lines during dispatch, bootstrap, and reap under a documented convention (a `container=<name>` correlation id spanning host terminal, `console.log`, and `meta.json`; [ward#517](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/517), see [container-lifecycle-logs.md](container-lifecycle-logs.md)); the [director read-only surface](agent-surface.md) binds a disk-sink drain dir read-only at `/opt/ward-agent-logs` so a director reads run logs without a docker socket ([ward#525](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/525)), and the director now joins the tailnet by default and mounts the read-only `ward ops eco observe` surface, so it can inspect the live kai-server - unit status, a journal tail, the `Mods/` + `Configs/` listings, and non-secret config reads - without mutation ([ward#547](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/547)); the bound source is a **redacted** parallel drain tree scrubbed by the same redaction the SigNoz export uses ([ward#526](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/526)). See [agent-observability.md](agent-observability.md).
- **`ward agents list [--json]`** - dump the fleet roster from `fleetconfig.Fleet`; `--json` is the stable read surface [agentic-os](https://github.com/coilysiren/agentic-os) (`aos`) reads ([ward#417](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/417)). See [agents-list](agents-list.md).
- **Selectable GitHub token source** *([ward#533](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/533))* - the GitHub dispatch lane provisions its token per `WARD_GITHUB_TOKEN_SOURCE`, defaulting to `env` (the publishable static-env-var path): `env` reads `WARD_GITHUB_TOKEN`/`GH_TOKEN`/`GITHUB_TOKEN`, `gh` mints a fresh token host-side via `gh auth token`, and `app` ([ward#534](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/534)) mints a short-lived, repo-scoped GitHub App installation token at dispatch: it signs an RS256 App JWT from a private key fetched from an operator-configured SSM param (`WARD_GITHUB_APP_ID` + `WARD_GITHUB_APP_KEY_SSM`), resolves the target repo's installation, and exchanges the JWT for a token scoped to that one repo. Resolution stays host-side and env-only in-tree - the App key's SSM param name rides an env var, never a baked path. See [agent-github.md](agent-github.md).
- **Audited raw Forgejo-token surface** *([ward#239](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/239))* - the plain `FORGEJO_TOKEN` is read only in a small, documented set of sites - the two resolver chokepoints (`forgejoTokenResolver`, `resolveForgejoToken`) every forge consumer funnels through, which try the [broker](broker.md) first, plus three root-only plumbing sites (broker daemon, entrypoint git-cred seed, reaper) that run outside the dropped-agent boundary. A build-time guard (`cmd/ward/forgejo_token_guard_test.go`) freezes that set: a new ad-hoc `os.Getenv("FORGEJO_TOKEN")` in any other file fails the build, forcing future forge access through a resolver rather than a fresh raw read. The full token-drop cutover ([ward#608](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/608), [ward#161](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/161)) stays blocked on a cli-guard read op; this keeps the surface from growing meanwhile. See [forgejo-token-audit.md](forgejo-token-audit.md).

## Agent harness seam

- **Per-agent folders own their behaviour** *([ward#425](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/425))* - each harness is an `agentsapi.Agent` in `internal/agents/<name>/` owning its capability bodies; core dispatches through the registry by feature-test (no per-agent `switch`); a ratchet blocks its return. See [agentsapi.md](agentsapi.md).

## Spec-driven ops (`ward-kdl`)

`ward-kdl` is the build-time authoring layer ([docs/ward-kdl.md](ward-kdl.md)): permission surfaces + fleet configs for `ops`, `docker`, `agents`, `pkg` ([surface](ward-kdl-surface.md)), plus `ward-kdl.fleet.kdl` and the staged container-topology overlay `ward-kdl.topology.kdl`. It builds into `ward-kdl-{read,write,admin}` tiers ([ward#240](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/240)) - not public artifacts ([ward#455](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/455)), authors build from a clone ([authoring](ward-kdl-authoring.md)). Two exceptions publish to an **internal** Forgejo package channel keyed to the release tag: `publish-kdl-write` pushes the `write` tier the broker reads ([ward#501](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/501), [broker.md](broker.md)), and `publish-kdl-read` pushes the `read` tier a sealed read-only director pulls for its non-mutating observe surface ([ward#547](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/547), [ward#572](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/572)). The build reads its spec bundle straight from the tracked `.ward/ward-kdl/` tree (the assets-dir convention, [ward#453](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/453)); [examples/ward-specs/](ward-kdl-authoring.md#bring-your-own-specs) is the neutral swap-in starter. The shipped binary is **config-driven at launch** ([ward#653](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/653), epic [ward#650](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/650)): the KDL build sites compile from an `fs.FS` selected by `WARD_CONFIG_REF`, the runtime stamps the resolved bundle sha into audit rows, and the container path now resolves its topology defaults through the same bundle tier before falling back to the baked neutral default. See [config-source.md](config-source.md).

The **exec-dialect** guardfiles auto-mount at their `wrap` path; `git` / `pkg brew` keep hand-written surfaces ([ward#284](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/284)), plus a **ward=true-gated** `ward docker exec` shell-into-a-run leaf ([ward#220](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/220), [ward-docker-exec.md](ward-docker-exec.md)). See [in-ward](ward-kdl-in-ward.md).

## Examples & demo

- **`examples/toy/`** - ward's minimal, dependency-free managed repo (Makefile + `.ward/ward.yaml` with a `security:` block + a ward-kdl guardfile), the demo and spec-bundle anchor. See [example-repo.md](example-repo.md).
- **`examples/demo.sh`** *([ward#251](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/251), [ward#250](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/250))* - the runnable launch demo: one happy path (`ward exec test` + audit row + clean-tree gate) plus three danger classes refused live - repo danger via the hard cli-guard argv gate, infra/cloud danger (`kubectl`/`aws`) via the protected-binary hook, and **ops danger** via the compiled ward-kdl operator surface (`ward ops forgejo pr` answers `denied by policy`, credential-free, the one demo denial that is both hard and a real ops verb). Every denial is real ward output, honest about which mechanism holds ([enforcement-boundary.md](enforcement-boundary.md)). See [demo.md](demo.md).

## Release pipeline

- **Release notes** *([ward#486](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/486))* - "does it affect you" verdict. [release-notes.md](release-notes.md).
- **Dual-forge binary matrix** *([ward#454](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/454))* - `ward-{darwin,linux,windows}-{amd64,arm64}` (windows as `.exe` + per-asset `.sha256` sidecar for scoop, [ward#561](https://forgejo.coilysiren.me/coilyco-flight-deck/ward/issues/561)) + `SHA256SUMS`, built once per tag and published byte-identical to both the Forgejo and GitHub release pages, so their checksums match.
